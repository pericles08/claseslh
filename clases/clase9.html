Clase 9: Encapsulación de datos y Unidad Máxima de Transmisión

En esta clase se estudia cómo los datos se preparan para viajar por una red, qué información agrega cada capa del modelo de comunicación y por qué la MTU condiciona el tamaño máximo de los paquetes que pueden transmitirse sin fragmentación.

Encapsulación Modelo OSI TCP/IP Trama Ethernet MTU Fragmentación

Objetivos de aprendizaje

  • Comprender qué significa encapsular datos para transmitirlos por una red.
  • Relacionar cada capa del modelo OSI o TCP/IP con su unidad de datos.
  • Reconocer la estructura básica de una trama Ethernet.
  • Explicar qué es la MTU y por qué su tamaño influye en el rendimiento de una red.
  • Interpretar el proceso de fragmentación y sus posibles inconvenientes.
  • Realizar pruebas de consola en Windows para estimar la MTU efectiva.
Pregunta inicial para pensar: cuando enviamos un mensaje por internet, ¿viaja solamente el texto que escribimos o también viaja información agregada por la red?

1. ¿Qué es la encapsulación de datos?

La encapsulación es el proceso mediante el cual los datos generados por una aplicación se preparan para su transmisión por la red. A medida que el mensaje baja por las capas del modelo OSI o TCP/IP, cada capa agrega información de control llamada encabezado o header.

Por ejemplo, cuando una persona abre una página web, el navegador genera una solicitud. Esa información no se envía sola: cada capa agrega datos necesarios para que el mensaje pueda salir del equipo, circular por la red, llegar al destino correcto y ser interpretado por el receptor.

Relación entre capas, unidades de datos y encabezados

Capa del modelo OSI Unidad de datos Ejemplo de encabezado o información agregada
Aplicación Datos HTTP, FTP, DNS, SMTP.
Transporte Segmento o datagrama TCP o UDP. Incluye puertos de origen y destino.
Red Paquete IP. Incluye direcciones IP de origen y destino.
Enlace de datos Trama Ethernet. Incluye direcciones MAC y tipo de protocolo.
Física Bits Señales eléctricas, ópticas o de radiofrecuencia.
Idea clave: el dato original queda “envuelto” por información adicional. Esa información permite indicar puertos, direcciones IP, direcciones MAC, tipo de protocolo y controles de transmisión.

2. Analogía: enviar una carta por correo postal

Para comprender la encapsulación, puede pensarse en el envío de una carta. La carta no viaja sola: se coloca en un sobre, luego puede incluirse en una bolsa o paquete de distribución, y finalmente es transportada por un medio físico.

Analogía postal Equivalencia en redes
Carta escrita Datos de la aplicación.
Sobre con nombre y dirección Encabezado de capa de red con direcciones IP.
Paquete de envío con instrucciones postales Trama Ethernet con direcciones MAC y control de enlace.
Camión, avión o transporte real Capa física: cable, fibra óptica o señal inalámbrica.
Para debatir: si una dirección postal está mal escrita, ¿el problema se parece más a un error de IP, a un error de MAC o a un error de datos de aplicación?

3. Formato de una trama Ethernet

En una red local, los datos suelen transmitirse mediante tramas Ethernet. La trama contiene información necesaria para entregar el mensaje dentro de la LAN y para verificar si hubo errores de transmisión.

MAC destino y MAC origen

Permiten identificar qué interfaz de red envía la trama y qué interfaz debe recibirla dentro de la red local.

Tipo

Indica qué protocolo se transporta dentro de la trama, por ejemplo IPv4, IPv6 o ARP.

Datos

Contiene el paquete IP, que a su vez puede contener un segmento TCP o un datagrama UDP.

CRC / FCS

Permite detectar errores de transmisión. Si la verificación falla, la trama se descarta.

4. ¿Qué es la MTU?

La MTU, sigla de Maximum Transmission Unit, es la Unidad Máxima de Transmisión. Indica el tamaño máximo que puede tener una unidad de datos, usualmente un paquete IP, para circular por una red sin necesidad de fragmentarse.

En redes Ethernet estándar, la MTU más común es de 1500 bytes. Esto significa que el paquete IP transportado como carga útil de la trama Ethernet no debería superar ese tamaño.

5. ¿Qué pasa si un paquete excede la MTU?

Si un paquete supera la MTU del enlace, pueden ocurrir dos situaciones principales.

Fragmentación

El paquete se divide en partes más pequeñas para poder transmitirse. Cada fragmento necesita su propia información de control, por lo que aumenta la cantidad de datos transmitidos.

Error o descarte

Si el paquete tiene activada la opción Don’t Fragment y supera la MTU, no puede dividirse. En ese caso, se genera un error y el paquete puede descartarse.

¿Por qué conviene evitar la fragmentación?

  • Incrementa el tráfico, porque cada fragmento requiere encabezados.
  • Aumenta el procesamiento en dispositivos intermedios y en el receptor.
  • Si se pierde un fragmento, puede fallar la reconstrucción completa del paquete.
  • Puede afectar el rendimiento de aplicaciones sensibles a latencia o pérdida.
Mecanismo relacionado: muchas redes intentan evitar la fragmentación mediante Path MTU Discovery, un procedimiento que busca descubrir cuál es la MTU máxima posible en el camino entre origen y destino.

6. Ejemplo práctico del impacto de la MTU

Supongamos que se envía una imagen de 4500 bytes por una red Ethernet con MTU de 1500 bytes.

  1. La aplicación genera los datos de la imagen.
  2. Las capas inferiores agregan encabezados para poder transmitirlos.
  3. Como el tamaño supera la MTU, el paquete puede necesitar fragmentarse.
  4. Cada fragmento debe incluir su propia información de control.
  5. Si la opción “Don’t Fragment” está activa y el paquete excede la MTU, el envío puede fallar.
Para analizar: ¿por qué un problema de MTU puede hacer que algunas páginas carguen, pero otras queden incompletas o funcionen lentamente?

Actividad 3 – Medir la MTU efectiva con ping -f -l

Objetivo: determinar el tamaño máximo de paquete que puede enviarse sin fragmentación. El parámetro -f indica que no se permite fragmentar el paquete. El parámetro -l, letra L minúscula, indica el tamaño del paquete en bytes.

Ejemplo de comando

ping 8.8.8.8 -f -l 1472
¿Por qué 1472 y no 1500? Porque el encabezado IP más el encabezado ICMP ocupan 28 bytes. Entonces: 1500 - 28 = 1472. En una red Ethernet estándar, 1472 bytes suele ser el mayor tamaño de carga ICMP que no debería fragmentarse.

Paso a paso sugerido

  1. Probar con un tamaño seguro.
  2. Probar el límite típico.
  3. Probar un valor que exceda el límite.
ping 8.8.8.8 -f -l 1000

ping 8.8.8.8 -f -l 1472

ping 8.8.8.8 -f -l 1473

Actividad 4 – Determinar la MTU máxima por búsqueda binaria

Objetivo: encontrar el valor máximo exacto, entre 1400 y 1500, para tu red. La búsqueda binaria consiste en probar valores intermedios para acercarse rápidamente al límite.

Método de prueba progresiva

ping 8.8.8.8 -f -l 1450
ping 8.8.8.8 -f -l 1460
ping 8.8.8.8 -f -l 1470
ping 8.8.8.8 -f -l 1472
ping 8.8.8.8 -f -l 1473

Cuando empiecen a fallar los pings con el mensaje de fragmentación, el valor anterior corresponde al máximo útil para la carga ICMP. Para estimar la MTU, se deben sumar 28 bytes.

8. Conclusión

Encapsulación

Permite preparar datos de forma ordenada para que puedan transmitirse por la red.

Trama Ethernet

Incluye direcciones MAC, tipo de protocolo, datos y control de errores.

MTU

Determina cuánto puede enviarse de una vez sin fragmentación.

Síntesis: cada capa agrega información para que la comunicación sea posible. Sin embargo, esa información también ocupa espacio. Por eso, comprender la MTU permite analizar problemas de rendimiento, fragmentación y conectividad.

11. Glosario mínimo

Encapsulación
Proceso por el cual cada capa agrega información de control a los datos que serán transmitidos.
Header o encabezado
Información agregada por una capa para que el receptor pueda procesar correctamente los datos.
Segmento
Unidad de datos asociada habitualmente a la capa de transporte cuando se usa TCP.
Paquete
Unidad de datos de la capa de red, generalmente asociada al protocolo IP.
Trama
Unidad de datos de la capa de enlace, por ejemplo una trama Ethernet.
MTU
Unidad Máxima de Transmisión. Define el tamaño máximo que puede tener un paquete para transmitirse sin fragmentación.
Fragmentación
Proceso de división de un paquete en partes más pequeñas para poder atravesar una red con MTU menor.
DF
Don’t Fragment. Opción que indica que un paquete no debe fragmentarse.
