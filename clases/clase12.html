Presentación y objetivos

Del número binario a la planificación de redes y rutas.

Una dirección IP no es solamente una secuencia de cuatro números. Es una herramienta de la capa de red que permite identificar interfaces, distinguir redes y hosts, calcular destinos locales, seleccionar puertas de enlace y construir esquemas de direccionamiento escalables.

Al finalizar la clase podrás

  • convertir valores entre decimal y binario;
  • interpretar direcciones IPv4 de 32 bits;
  • identificar red, host, máscara, broadcast y rango asignable;
  • reconocer clases y direcciones especiales;
  • distinguir direcciones públicas y privadas;
  • calcular subredes con FLSM y VLSM;
  • interpretar prefijos CIDR y realizar agregación de rutas;
  • leer tablas de enrutamiento y una configuración real de Windows;
  • comprender la estructura básica de IPv6.

Criterio de integración

Los materiales combinan explicaciones actuales con ejercicios que utilizan convenciones históricas. En esta clase se conserva esa perspectiva histórica, pero los cálculos principales utilizan subnetting moderno: las subredes “todo ceros” y “todo unos” son utilizables.

Importante. El direccionamiento por clases se estudia como fundamento histórico y pedagógico. En redes actuales, el tamaño de una red se expresa principalmente mediante prefijos CIDR, por ejemplo 192.168.10.0/24, 10.0.0.0/20 o 172.16.4.0/22.
Fundamento 1
1

¿Qué es una dirección IP?

Identificación lógica en la capa de red.

IP significa Internet Protocol. Una dirección IP es una dirección lógica utilizada por una interfaz para participar en una red IP. Opera en la capa 3 (Red) del modelo OSI y no debe confundirse con la dirección MAC, que pertenece a la capa de enlace.

Red

Identifica el conjunto lógico al que pertenece el dispositivo.

Host

Identifica una interfaz concreta dentro de esa red.

Router

Utiliza prefijos IP para decidir cómo reenviar paquetes entre redes.

Unicidad. Dentro de una misma red, dos interfaces no deben utilizar simultáneamente la misma dirección IP: se produciría un conflicto de direccionamiento.
  1. Explicá por qué una IP es una dirección lógica y una MAC se considera una dirección de enlace.
  2. Indicá qué dispositivo utilizaría principalmente direcciones IP para decidir el camino hacia otra red: switch o router.
  3. ¿Qué problema puede aparecer si dos computadoras de la misma LAN usan la misma IPv4?

Estructura de una dirección IPv4

32 bits divididos en cuatro octetos.

IPv4 utiliza 32 bits, agrupados en cuatro octetos de 8 bits. Cada octeto puede representar valores entre 0 y 255. La forma habitual es la notación decimal punteada.

192. 168. 3. 24 
11000000.10101000.00000011.00011000
192      .168      .3       .24
1 octeto = 8 bits = 256 valores (0 a 255)
IPv4 = 32 bits = 2³² direcciones posibles
Notación. Es preferible escribir 192.168.1.1 y no 192.168.001.001, evitando ceros innecesarios a la izquierda.

Fundamento 4
4

Parte de red, parte de host y prefijo

La máscara determina dónde termina la red y dónde comienza el host.

Toda dirección IPv4 puede interpretarse como una combinación de prefijo de red y parte de host. El prefijo es común a los dispositivos de la misma subred; los bits de host distinguen interfaces dentro de ella. 

IP:       192.168.1.25
Máscara:  255.255.255.0
Prefijo:  /24

Red:      192.168.1.0
Host:                 25

Dirección de red

Se obtiene colocando en 0 todos los bits de host. Identifica a la subred y no se asigna a un host normal.

Dirección de broadcast

Se obtiene colocando en 1 todos los bits de host. Representa un envío hacia todos los hosts de esa subred IPv4.

Usando las máscaras tradicionales, señalá qué octetos representan red y cuáles host:

  • 10.250.1.1
  • 150.10.15.25
  • 192.14.2.90

¿Qué es loopback?

El loopback permite que un sistema envíe tráfico hacia sí mismo sin salir a la red física. Es útil para verificar la pila TCP/IP local y para comunicaciones internas entre procesos. 

ping 127.0.0.1

Direcciones públicas, privadas y NAT

Separar el direccionamiento interno del direccionamiento global.

Dirección privada

Se utiliza dentro de redes internas y no se enruta directamente por Internet. Puede reutilizarse en organizaciones distintas.

Dirección pública

Es globalmente enrutable cuando forma parte de un bloque público asignado y debe ser única en su contexto global.

Bloque privadoRangoPrefijo
1010.0.0.0 - 10.255.255.255/8
172172.16.0.0 - 172.31.255.255/12
192.168192.168.0.0 - 192.168.255.255/16

NAT

Network Address Translation permite traducir direcciones privadas al comunicarse con redes externas. En una vivienda, varios equipos privados pueden compartir la conectividad pública del router.

PC 192.168.1.20 → Router / NAT → IP pública → Internet
Conflictos de direccionamiento. Utilizar internamente un bloque público que pertenece a otra organización puede generar problemas cuando la red se conecta a Internet, porque las rutas globales conducen ese bloque hacia su propietario real.

Clasificá: 10.1.2.3, 172.15.1.1, 172.20.8.5, 192.168.100.25, 8.8.8.8, 127.0.0.1.

Subnetting de tamaño fijo (FLSM)

Tomar bits de host para crear varias subredes del mismo tamaño.

El subnetting divide un bloque en redes menores. Si se “toman prestados” s bits de la parte de host, se generan 2ˢ subredes. Si quedan h bits para host, cada subred posee 2ʰ direcciones y, en el esquema IPv4 clásico con red y broadcast, 2ʰ - 2 hosts.

Subredes modernas = 2^s
Hosts = 2^h - 2
Convención histórica de algunos ejercicios. Materiales antiguos restaban dos a la cantidad de subredes por considerar no utilizables la subred “todo 0” y la subred “todo 1”. En redes CIDR modernas esas subredes pueden utilizarse. Cuando un ejercicio indique explícitamente “subredes útiles” según la convención histórica, puede aparecer 2ˢ - 2.

Ejemplo: 192.168.10.0/24 dividido en /27

Prefijo original: /24
Nuevo prefijo:    /27
Bits prestados:   3
Subredes:         2³ = 8
Bits de host:     5
Direcciones:      2⁵ = 32 por subred
Hosts clásicos:   30 por subred
Incremento:       32

Para una red 192.168.50.0/24, elegí el prefijo mínimo que permita:

  • 100 hosts
  • 60 hosts
  • 30 hosts
  • 14 hosts
  • 6 hosts
  • 2 hosts
Comprobar
100→/25 · 60→/26 · 30→/27 · 14→/28 · 6→/29 · 2→/30.

VLSM: máscaras de longitud variable

Asignar a cada segmento el bloque que realmente necesita.

VLSM permite utilizar prefijos diferentes dentro de un mismo bloque global. El objetivo es evitar que todas las subredes tengan que adoptar el tamaño de la más grande.

Reglas de un bloque VLSM

  • Su tamaño debe ser una potencia de 2.
  • Debe comenzar en una dirección alineada, múltiplo de su tamaño.
  • No debe solaparse con otro bloque.
  • Conviene asignar primero las redes de mayor tamaño.

Procedimiento

  1. Ordenar las redes de mayor a menor cantidad de hosts.
  2. Sumar dos direcciones para red y broadcast.
  3. Redondear hacia arriba a la siguiente potencia de 2.
  4. Calcular el prefijo: 32 - bits necesarios para el tamaño del bloque.
  5. Asignar la primera dirección de red y avanzar según el tamaño de bloque.
  6. Calcular broadcast como red + tamaño de bloque - 1.
  7. Asignar direcciones a interfaces, evitando red y broadcast.

CIDR reemplaza el reparto rígido por clases y permite utilizar prefijos de longitud adecuada a la necesidad real. También posibilita representar varias redes contiguas mediante un prefijo más corto.

Sumarización o agregación de rutas

Reducir entradas de enrutamiento mediante un prefijo común.

Si varias redes se alcanzan por la misma acción de reenvío, pueden representarse mediante un prefijo común. Esto reduce la cantidad de entradas que un router debe consultar. 

172.17.0.0/16
172.19.0.0/16

Prefijo binario común: 14 bits
Resumen posible: 172.16.0.0/14

ATENCIÓN: ese resumen también cubre 172.16.0.0 y 172.18.0.0.
No toda sumarización es conveniente. Debe verificarse que las redes incluidas en el prefijo resumido tengan una política de reenvío compatible. Diseñar bloques contiguos desde el inicio facilita la agregación.

Una sede posee las redes 172.20.0.0/24, 172.20.1.0/24, 172.20.2.0/24 y 172.20.3.0/24, todas detrás del mismo router. Proponé una ruta resumen e indicá qué rango cubre.

Comprobar
172.20.0.0/22, que cubre 172.20.0.0 a 172.20.3.255.

Gateway, DHCP, DNS y asignación de direcciones

La IP necesita otros parámetros para integrarse en una red real.

Gateway

Dirección del router al que se envía tráfico destinado a redes diferentes.

DHCP

Asigna automáticamente IP, máscara, gateway, DNS y otros parámetros a los clientes.

DNS

Relaciona nombres de dominio con direcciones IP para facilitar el acceso a servicios.

En muchos diseños se reserva una dirección temprana del rango, por ejemplo el primer host, para el router, aunque esto es una convención de administración y no una obligación matemática. Servidores y routers suelen recibir direcciones estáticas; los clientes pueden recibirlas mediante DHCP.

  • Gateway: 192.168.20.1 o 192.168.30.1.
  • DNS: puede estar dentro o fuera de la LAN, siempre que exista una ruta para alcanzarlo.
  • ¿Qué componente podría entregar automáticamente esos datos?

Introducción a IPv6

128 bits, hexadecimal, jerarquía y ausencia de broadcast.

IPv6 amplía el espacio de direccionamiento de 32 a 128 bits. Se representa mediante ocho grupos hexadecimales de cuatro dígitos separados por dos puntos. 

Forma completa:
2001:0DB8:0000:0000:0002:0000:5555:4777

Sin ceros iniciales:
2001:DB8:0:0:2:0:5555:4777

Compresión:
2001:DB8::2:0:5555:4777
Regla de compresión. La sustitución de una cadena continua de grupos cero por :: se realiza una sola vez dentro de una dirección, porque de otro modo no podría reconstruirse su longitud sin ambigüedad.
TipoReferenciaFunción
Unicast global2000::/3Direccionamiento global.
Link-localFE80::/10Comunicación dentro del enlace local.
MulticastFF00::/8Comunicación hacia grupos.
Loopback::1/128Propio host.
Unique localFC00::/7Ámbito interno.

Un esquema organizacional frecuente parte de un prefijo /48 y utiliza 16 bits adicionales para identificar subredes /64. IPv6 no utiliza direcciones de broadcast: se apoya, entre otros mecanismos, en multicast.

  1. Comprimí 2001:0DB8:0000:0000:0000:0000:0000:0045.
  2. Expandí 2001:DB8:1::25 a ocho grupos de cuatro dígitos.

Si una organización recibe 2001:5:5::/48, escribí cinco subredes /64 utilizando el cuarto grupo hexadecimal para numerarlas.

  4. ¿Por qué una ruta /24 tiene prioridad sobre una /16 si ambas coinciden con el destino?
  5. ¿Por qué una IP privada necesita NAT para comunicarse directamente con Internet?

Desafío integrador: diseñar una red institucional

Articular direccionamiento, subredes, gateway, NAT y rutas.

Una institución recibe para su LAN el bloque privado 172.16.0.0/16 y necesita organizar:

  • Administración: 200 hosts.
  • Laboratorio: 120 hosts.
  • Docentes: 60 hosts.
  • Biblioteca: 30 hosts.
  • Dos enlaces punto a punto entre routers: 2 hosts cada uno.
  1. Ordená los segmentos para aplicar VLSM.
  2. Asigná a cada uno dirección de red, prefijo, máscara, rango de hosts y broadcast.
  3. Elegí una dirección de gateway para cada LAN.
  4. Explicá cómo accederían a Internet mediante NAT.
  5. Proponé una ruta por defecto para los routers internos.
  6. Indicá qué bloques podrían organizarse para facilitar sumarización.
  7. Como extensión, suponé que la institución recibe 2001:DB8:CAFE::/48 y asigná una /64 a cada segmento.

Glosario y fuentes de trabajo

Vocabulario esencial y materiales integrados.

AND
Operación booleana utilizada entre una dirección IP y su máscara para obtener la dirección de red.
Broadcast
Dirección IPv4 que representa a todos los hosts de una subred determinada.
CIDR
Direccionamiento sin clases que expresa la longitud del prefijo mediante /n.
DHCP
Protocolo de configuración dinámica de hosts.
DNS
Sistema que relaciona nombres con direcciones IP.
FLSM
Esquema de subnetting en el que todas las subredes utilizan la misma máscara y tamaño.
Gateway
Próximo salto utilizado para alcanzar redes que no son locales.
Host
Interfaz o dispositivo direccionable dentro de una red.
IPv4
Versión de IP con direcciones de 32 bits.
IPv6
Versión de IP con direcciones de 128 bits representadas en hexadecimal.
Loopback
Dirección que apunta al propio sistema; en IPv4 se reserva 127.0.0.0/8.
Máscara
Patrón de 32 bits que separa prefijo de red y parte de host en IPv4.
NAT
Traducción de direcciones de red entre distintos espacios de direccionamiento.
Prefijo
Conjunto inicial de bits que identifica una red o bloque.
Ruta por defecto
Ruta 0.0.0.0/0 utilizada cuando no existe una coincidencia más específica.
Subnetting
Proceso de dividir un bloque IP en subredes más pequeñas.
Sumarización
Representación de varias rutas mediante un prefijo común.
VLSM
Uso de máscaras de longitud variable para asignar bloques de distintos tamaños.
